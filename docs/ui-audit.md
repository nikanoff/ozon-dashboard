## 1. Техническое состояние: здоровое

| Проверка | Результат |
| --- | --- |
| `vitest run` | **58 тестов в 5 файлах — все проходят** |
| `svelte-check` | **0 ошибок, 0 предупреждений** |
| `vite build` | собирается за ~2.5 с, без предупреждений |
| Дерево git | чистое, история осмысленная |

Вес клиента замерен по прод-сборке:

- JS: крупнейшие чанки 43.9 / 26.0 / 21.3 / 18.7 КБ, суммарно ~140 КБ raw;
- CSS: 20.0 КБ (дашборд) + 6.5 КБ (хедер) + 5.4 КБ (остатки) + 1.9 КБ (layout) ≈ 34 КБ raw.

То есть **проблема не в размере бандла**. Svelte-код аккуратный, логика метрик вынесена
в `src/lib/*` и покрыта тестами, серверные эндпоинты не превращены в открытый релей,
ключи нигде не логируются. Это редкий случай, когда «сначала дизайн-система, потом
фичи» — правильный порядок.

### Что уже сделано хорошо (не ломать)

- Настоящие `<a>` и `<button>` в разметке — **ни одного `div`-кнопки** на дашборде.
- У каждого набора данных есть ветка пустого состояния.
- `RangeToggle` — с `role="group"`, `aria-label` и `aria-pressed`.
- `InfoTip` закрывается по `focus`, есть `aria-hidden` на декоративных SVG.
- `offline.html` и `manifest.webmanifest` сделаны по-взрослому (maskable-иконки,
  `shortcuts`, `display_override`, `lang: "ru"`).
- `sw.js`: network-first для навигации, обход `/api/*`, отдельные кэши, `skipWaiting`.
- Брейкпоинты 1024 / 768 / 640, бенто-сетка корректно схлопывается в колонку.
- Таблица заказов сгруппирована по `posting` через `rowspan` — структура верная.

## 2. P0 — исправить первым (ломает UX или падает)

### P0-1. Первый экран показывает нули вместо загрузки

Скелетоны нарисованы только для таблицы заказов: единственное использование
`$isLoading` в файле — `routes/+page.svelte:976`. Все аналитические блоки выводят
значения из `stats`, выведенного из пустого массива (`:147-151`), поэтому на первой
загрузке (31 день = 1–2 с) продавец видит «Calendar Day — **0 ₽**», нулевую KPI-полосу
и пустые графики. Отличить это от «сегодня не было продаж» невозможно.

Отдельно: строка `:98` деструктурирует только `{ data, dispose }`, поэтому
`stocksResult.error` и `stocksResult.isLoading` не читаются вообще. В результате
`{#if stockRows.length === 0}` (`:841-845`) одинаково означает «ещё грузится»,
«запрос упал» и «остатков нет» — текст сообщения при этом утверждает третье.

**Фикс.** Загейтить бенто и KPI-полосу на `$isLoading` (скелетоны тех же размеров),
развести три состояния остатков по `isLoading` / `error` / пустой массив, дать retry.

### P0-2. Два разных числа под одним названием «выручка за 24 часа»

Проверено по коду:

- «Last 24 Hours» (`:454-476`) печатает `stats.last24h.netSum` — **net**, за вычетом
  отмен (`lib/stats.ts:177`);
- «Выручка за 24ч» в KPI-полосе (`:545-557`) печатает `deltas.last24h.revenue` —
  **gross**, отмены включены (`lib/metrics.ts:30-39`, сумма `postingTotal` без фильтра).

Разница между ними — ровно сумма отмен, и ни одна подпись об этом не говорит.
То же для 7 дней (`:478-501` против `:558-570`). Дополнительно соседствуют календарные
и скользящие окна без объяснения: «Calendar Day» ↔ «Last 24 Hours», «Calendar Week» ↔
«Last 7 Days», «Calendar Month» ↔ «Last 31 Days». При этом шапка KPI-полосы говорит
«текущий месяц» (`:532`), а два чипа из восьми — скользящие 24ч/7д.

**Фикс.** Одно число — один смысл. Явные подписи «календарный день (с 00:00)» против
«последние 24 часа», и явное «без отмен» / «с отменами». Ошибку типов лучше закрыть
типом: `netSum` и `sum` уже разные поля — не выводить их под одним ярлыком.

### P0-3. Ключ `{#each}` может уронить всю таблицу заказов

`routes/+page.svelte:986`:

```svelte
{#each posting.products as product, i (product.sku || product.name)}
```

В одном отправлении Ozon один и тот же SKU может встретиться дважды (заказ разбит на
строки), а товары без SKU схлопываются в `product.name`. Дубликат ключа — не
предупреждение: в `svelte/src/internal/client/errors.js:136-148` функция
`each_key_duplicate` **бросает исключение и в dev, и в prod** (в prod — без деталей,
но `throw`). Проверено в исходниках установленной версии Svelte 5.

**Фикс.** `(product.sku || product.name) + '-' + i`.

### P0-4. Пагинация оставляет пользователя на пустой странице

`currentPage` (`:214`) нигде не ограничивается при уменьшении `postingsData`.
Автообновление раз в 5 минут меняет число строк, и пользователь на 12-й странице
увидит «Page 12 of 8», заблокированную кнопку Next и «No orders found.» (`:1146-1148`) —
неотличимо от «заказов нет вообще».

**Фикс.** `$effect`, зажимающий `currentPage` в `Math.max(1, totalPages)`.

### P0-5. Автообновление невидимо и не озвучивается

`refreshInterval: 5 * 60 * 1000` (`:70`, `:95`). Единственный индикатор на странице —
`<span class="live-indicator">` (`:326`): статичная зелёная точка без текста, без
анимации, без `aria-hidden`, и она **горит даже когда запрос упал**. Нет ни отметки
«обновлено в 14:32», ни `aria-live`, ни признака устаревших данных. Пользователь не
может понять, данным 5 секунд или 5 часов.

Усугубляется тем, что `lib/swr.ts:92-96` при ошибке фонового обновления сохраняет
старые `data` и выставляет `error` — то есть карточка ошибки (`:295-313`) может висеть
над молча устаревшими числами.

**Фикс.** `aria-live="polite"` регион + видимая относительная метка времени; точка
реагирует на `$isValidating`; при наличии stale-данных — плашка «показаны данные за …».

### P0-6. Ключ SWR-кэша зафиксирован при инициализации

`routes/+page.svelte:41`:

```ts
const clientId = get(ozonKeys).clientId;   // одноразовое чтение стора
const cacheKey = `ozon-dashboard:${clientId}`;
```

`useSWR` принимает ключ как обычную строку (`lib/swr.ts:41-45`), кэш — модульный `Map`.
Комментарий на `:45` обещает «cached data must not outlive a credentials change», но при
смене Client ID ключ не меняется. Сценарий с реальным искажением данных:

1. аккаунт A загружен в ключ `ozon-dashboard:A`;
2. пользователь переключился на B → `refreshOnKeysChange` (`:101-104`) пишет данные B
   **в ключ A**;
3. возврат на A → `peekCache` (`:54`) отдаёт данные **B**, `needsFullLoad` возвращает
   false, и `mergeDashboardPayload` склеивает заказы двух аккаунтов в одну таблицу.

**Фикс.** `$derived`-ключ + передача ключа геттером (или пересоздание SWR при смене
ключей).

## 3. P1 — заметные улучшения

### 3.1. Шрифт не покрывает язык интерфейса (проверено)

`src/app.css:1` подключает `Plus Jakarta Sans`, объявленный и для заголовков, и для
тела (`--font-heading` / `--font-body`, строки 4-5). Но у семейства **нет базового
подмножества `cyrillic`**: в `@fontsource/plus-jakarta-sans` есть только `cyrillic-ext`,
`latin`, `latin-ext`, `vietnamese`, а `cyrillic-ext` — это диапазон
`U+0460-052F,U+1C80-1C88,…`, то есть **историческая кириллица**, без `U+0410-044F`
(А–Я, а–я) и `U+0401` (Ё). Косвенно это подтверждает размер файла: ~1 КБ woff2 на
начертание.

Практическое следствие: все русские подписи («Ключевые показатели», «Остатки и
оборачиваемость», «Средний чек») рисуются системным фолбэком, а латиница и цифры
(«Net Sales», «Calendar Day», «Orders», «1 234») — Plus Jakarta Sans. На одной
странице два разных шрифта, метрики которых не совпадают → рваная базовая линия и CLS.

Дополнительно: шрифт подключён через `@import` **внутри** `app.css`, то есть
обнаруживается только после разбора CSS, а `preconnect` в `app.html:34-35` этому не
помогает. Комментарий на `routes/+page.svelte:1159` («Moved to app.html for zero CLS»)
не соответствует `app.html`, где ссылки на шрифт нет.

**Фикс.** Выбрать шрифт с настоящей кириллицей (Inter, Manrope, Onest, Golos Text) и
подключить self-hosted `woff2` с `<link rel="preload">` в `app.html` плюс
`font-display: swap` и метрик-совместимый фолбэк. Или, как минимальный шаг, убрать
`Plus Jakarta Sans` из `--font-body` и оставить системный стек.

### 3.6. Графики: информация доступна только через `title`

Единственный канал данных в тренде и часовом графике — атрибут `title` (`:591`, `:637`):
он недостижим с клавиатуры, ненадёжен для скринридеров и **невозможен на тач-экране**.
На телефоне два графика нечитаемы — видны только первая и последняя дата.

Плюс:
- ноль рисуется как ненулевой столбик: `Math.max(2, …)` (`:595`) и
  `point.orders === 0 ? 2 : …` (`:644-647`) дают 2–3 px на пустой день;
- нет оси значений, сетки, подписей и единиц — сравнить можно, прочитать число нельзя;
- `.diamond-text` (`:1633-1645`) без `tabular-nums` (он есть только у `.kpi-value`,
  `:1823`) → крупные суммы дёргаются на каждом обновлении.

### 3.7. Два графика под одним переключателем считают разные окна

`dailyTrend` (`lib/metrics.ts:119-136`) — N **календарных** дней включая сегодняшний
(неполный), `hourlyActivity` (`lib/metrics.ts:411-417`) — **скользящие** `now − N·24ч`.
И то и другое подписано `{windowDays} дн.` (`:576`, `:619`), поэтому суммы не сойдутся
никогда. Семантика выручки тоже разная: тренд рисует `netRevenue`, часовой график —
gross и **выбрасывает отменённые** (`lib/metrics.ts:420`).

### 3.8. Форматирование чисел и дат непоследовательно

- `formatPercent` (`:125-127`) через `toFixed(1)` даёт `12.3%` с **точкой**, тогда как
  валюта и числа — `ru-RU` (`:110-123`): «Доля отмен» (`:189`), «Штук в заказе»
  (`:190`) и все дельты (`:552-568`) печатаются с точкой. По-русски нужно `12,3 %`.
- Нет сокращения больших чисел: `maximumFractionDigits: 0` печатает все разряды, а
  hero-значение рендерится в `clamp(2.5rem, 4vw, 4.5rem)` (`:1648`) без `overflow-wrap`
  и `min-width: 0` — 8–9-значная сумма вылезет из карточки.
- Символ `₽` в hero и средних карточках стоит **перед** числом (`:329`, `:380`, `:421`),
  а во всех остальных местах — после; при этом `.replace("₽","").trim()` повторяется
  шесть раз (`:332`, `:376`, `:417`, `:457`, `:482`, `:507`).
- Даты: таблица через `toLocaleString("ru-RU")` (`:994-1001`), ось тренда — сырой ISO
  (`:601-602`).

### 3.9. Таблица: семантика и читаемость

- Нет `<caption>` и `scope="col"` на `<th>` (`:963-973`) — ровно там, где пять колонок
  из восьми используют `rowspan`.
- `alt={product.name}` (`:1014`) дублирует соседнюю ссылку с тем же текстом
  (`:1051-1057`) — скринридер читает название дважды.
- Плейсхолдер отсутствующей картинки (`:1022-1048`) не содержит текста вообще.
- Зебра `tbody tr:nth-child(even)` (`:1393`) чередуется по **строке товара**, а не по
  отправлению, и визуально разрушает группировку `rowspan`.
- `thead { position: sticky; top: 0 }` (`:1357-1361`) не работает: скролл-порт — это
  `.table-container` с `overflow-x: auto` (`:1340-1346`), а по вертикали он не скроллится.
- Дублирующая логика скруглений: `th:first/last-child` (`:1375-1381`) и последняя
  строка `td` (`:1413-1419`) поверх радиуса самого контейнера (`:1342`).
- Ячейка `Total Price` (`:1062-1067`) — это сумма по строке, а не по заказу: итог
  отправления приходится складывать вручную, хотя выше есть «Средний чек».
- Нет сортировки, поиска, фильтра по статусу и размера страницы; `currentPage` не в
  URL, состояние нельзя переслать ссылкой.

### 3.10. Статус заказа: английский в таблице, русский в графике

`:1076` печатает сырой `posting.status` («delivering», «cancelled»), тогда как
`statusLabel()` (`:141`, словарь `STATUS_LABELS` в `lib/metrics.ts:436-442`) используется
в графике статусов (`:905`). Хуже того, стили `data-status` есть только для трёх
значений (`:1273-1286`), поэтому реальные `awaiting_packaging` и `awaiting_deliver`
получают **неоформленную** плашку: прозрачный фон, унаследованный цвет, капс 0.65 rem.

### 3.20. `InfoTip` обещает кнопку, но кнопкой не является

`lib/components/InfoTip.svelte:17`:

```svelte
<span class="info-tip" tabindex="0" role="button" aria-label={label}>
```

Пузырь (`:33`) помечен `role="tooltip"`, но связи с триггером нет: ни

(какое окно, net против gross) вынести видимым текстом, а не только в подсказку.

### 3.21. `InstallPrompt` умирает после первого отказа

`lib/components/InstallPrompt.svelte:78-88`:

```ts
await deferred.prompt();
const choice = await deferred.userChoice;
if (choice.outcome === "accepted") deferred = null;   // при отказе событие сохраняется
```

Событие `BeforeInstallPromptEvent` одноразовое: повторный вызов `prompt()` на нём

только той же кнопкой — ни клика вне, ни Escape; отказ нигде не сохраняется
(`localStorage` не используется), так что предложение возвращается при каждом заходе.

В `src/app.css` нет `color-scheme`, хотя `static/offline.html:11` его объявляет. На

**Фикс.** `color-scheme: dark` в `:root` в `src/app.css`; класс `.dark` либо определить,
либо убрать.

## 4. PWA и SEO

- **`static/favicon.svg` — 234 КБ** (1024×1024, 281 путь, ~280 разных заливок,
  автотрассировка растра). Проверено чтением файла: это белая картинка на фоне
  `#FBFBFC`, визуально не связанная с золотым ромбом из `static/icons/*` и
  `offline.html:71-83`. Итог — три разных знака бренда (favicon / иконки PWA / офлайн)
  и **белый квадрат в тёмной вкладке браузера**. При этом правильная графика уже лежит
  рядом: `icon-192.png` — 2.2 КБ, `icon-512.png` — 5.8 КБ (размеры сверены по IHDR
  PNG), и `favicon.svg` дополнительно прекешируется (`sw.js:16`).
- **Рендера нет вообще**: `routes/+page.ts:5` объявляет `ssr = false`, поэтому
  краулеры и превью-боты мессенджеров (Telegram/WhatsApp/Slack — они не выполняют JS)
  видят только `<head>` из `app.html` и пустой `<body>`: ни `<svelte:head>` дашборда
  (`+page.svelte:271-282`), ни страницы остатков (`stocks/+page.svelte:66-77`). Значит
  `/stocks` получает превью дашборда, а все og-теги внутри страниц — мёртвый код.
  При этом `robots.txt` разрешает индексацию, а `sitemap.xml` перечисляет страницы —
  приложение приглашает индексировать то, что нечего показать.
- **Нет `og:image`**, `og:url`, `og:locale`, `twitter:image` и `rel="canonical"`
  (`app.html:22-31`) — превью ссылки будет без картинки.
- `sitemap.xml` содержит **захардкоженный** `https://ozon-dashboard.vercel.app/` и
  фиктивный `lastmod 2025-01-01`; в `robots.txt` нет строки `Sitemap:` (и сам файл
  карты недостижим, если домен другой).
- `app.html:9`: `<title>Ozon</title>` — заглушка, которая и уходит в превью; в
  `manifest.webmanifest` у `shortcuts[].icons` (`:47`, `:53`) не указан `"type"`.
- `sw.js:9`: `VERSION = "v1"` — рукописный литерал, не связанный со сборкой, поэтому
  `activate` (`:33-45`) никогда не удаляет `ozon-static-v1`; прекеш перезаписывается на
  месте (`:28`), а старые `_app/immutable/*` и по одной HTML-странице на URL копятся
  без ограничения размера. Плюс `skipWaiting()` (`:29`) и `clients.claim()` (`:42`)
  подменяют воркер в открытых вкладках без уведомления пользователя, а состояние
  `updated` из SvelteKit не читается нигде — вкладка может бесконечно работать на
  старой сборке. Подставлять хэш сборки в `VERSION` и добавить приглашение обновления.
- `InstallPrompt` показывается только на мобильных (`lib/components/InstallPrompt.svelte:23-25`,
  сделано намеренно) — на десктопе установить PWA через UI нельзя вообще.
- Что действительно в порядке и не требует правок: все четыре иконки манифеста плюс
  `apple-touch-icon.png` существуют и совпадают с объявленными размерами (192, 512,
  512, 192, 180 — сверено по заголовкам PNG), maskable-знак вписан в безопасный круг;
  `viewport-fit=cover` + `env(safe-area-inset-*)` + `black-translucent` согласованы;
  масштабирование не запрещено; офлайн-страница прекешируется и используется как
  фолбэк навигации, а навигация идёт network-first — устаревший HTML в онлайне
  **не** отдаётся.

## 6. Чего делать не нужно

- **Не менять стек и не тянуть UI-кит.** Компонентов мало, токены уже есть — проблема
  в том, что они не применяются, а не в отсутствии библиотеки.
- **Не оптимизировать бандл.** ~140 КБ JS и ~34 КБ CSS — нормально; выигрыш будет
  в пределах шума. Реальный вес — favicon на 234 КБ и блокирующий `@import` шрифта.
- **Не переписывать `lib/metrics.ts` / `lib/stats.ts`.** Логика покрыта 58 тестами и
  корректна; из неё нужно только вытащить наружу разницу net/gross и согласовать окна.
- **Не добавлять тёмную/светлую тему «заодно».** Половина контраста в текущей палитре
  не проходит AA; вторая тема удвоит долг.
